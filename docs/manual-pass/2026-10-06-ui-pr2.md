## Fixes the pass found

Each is its own commit with its own test.

1. `88d15a3`: after an Equip pick, Enter on the ▶ row opened the next row's command window. The
   re-focus flag went up before `act` settled, and a drawing in between aimed the ring at a menu
   item about to vanish.
2. `509a70c`: after a tab switch the ring sat on a row of the old tab. A drawing already under way
   took the re-focus with the old stops.
3. `5a34812`: after a recruit inserted a row, Up went two rows up. The engine keeps the ring by
   position, so any change to the stops can part it from the ▶. The pane now puts the ring back on
   the ▶ whenever a drawing's stops differ from the last; this replaced fixes 1 and 2's flag.

## Notes

1. An inline pane gets the rows the layout spares, not the 24 it asks for: 14 body rows in a
   105 × 50 Terminal.app (measured), fewer in smaller windows. The windows need 16 (wide) or more
   (narrow), so an inline pane shows only "The pane needs more room." In fullscreen from 110
   columns the pane docks at full height and works, as above. Recorded in ADR 0005's PR 2 note.
2. The pane follows the band's renderer verdict. With the pane docked the band collapses to one
   row and never probes, so the pane drew raster in cmux until `/promptfall renderer image` was set.
   Settings live in the store, so Kevin's restored save keeps his own setting.
3. A pick message longer than the window is cut at the border ("…(pick 1 more").
4. The fake's bots post many identical buy orders: the sell window listed 83 at 180G, paged. Up
   from the first order wraps straight to Set a price.
